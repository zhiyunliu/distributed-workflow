# Build/Startup 验收口径（Scope）

## 1. 目标与边界
- 目标：统一“可交付最小可验收”口径，覆盖从编译到启动再到链路可用性的分级定义。
- 非目标：不在本文定义性能压测、安全渗透、容量规划、长期稳定性测试。
- 约束：仅作为计划与验收标准文档，不改动业务代码。

## 2. 分级验收定义

### L1 仅编译（Compile）
- 定义：后端与前端在当前分支可完成构建，无编译错误。
- 最低通过条件：
  - 前端构建命令成功退出（exit code = 0）。
  - 后端关键模块可完成编译（按仓库既有构建入口）。
- 证据：构建日志、产物目录或构建成功摘要。
- 失败判定：任一构建失败或需手工临时改代码才可通过。

### L2 进程启动（Startup）
- 定义：服务进程可在目标环境正常拉起，并在限定时间内进入可服务状态。
- 最低通过条件：
  - 进程启动后无立即崩溃。
  - 启动日志无阻断级错误（如配置缺失导致服务不可用）。
  - 关键端口监听成功（如 API/前端静态服务端口）。
- 证据：进程列表、端口监听结果、启动日志片段。
- 失败判定：进程反复重启、端口未监听、启动后短时间退出。

### L3 健康检查（Health Check）
- 定义：在 L2 基础上，系统关键健康探针可稳定返回“可用”。
- 最低通过条件：
  - 健康检查接口返回成功状态（HTTP 2xx 或项目约定成功码）。
  - 关键依赖就绪状态明确（数据库/配置中心/消息通道按实际启用项）。
  - 连续多次检查结果一致（建议至少 3 次，间隔 5-10 秒）。
- 证据：健康检查请求与响应记录、依赖就绪摘要。
- 失败判定：健康检查间歇失败、依赖未就绪但未降级处理。

### L4 端到端联通（E2E）
- 定义：在 L3 基础上，完成一条最小业务闭环链路验证。
- 最低通过条件：
  - 从入口到结果的最小关键路径成功执行一次。
  - 关键状态变化可观测（日志、数据库记录或接口返回）。
  - 无人工补偿或绕过动作。
- 证据：E2E 步骤记录、输入输出样例、结果截图/日志引用。
- 失败判定：链路中断、关键状态未落地、需人工干预才能完成。

## 3. 验收执行顺序（必须按级别递进）
1. 执行 L1。
2. L1 通过后执行 L2。
3. L2 通过后执行 L3。
4. L3 通过后执行 L4。

说明：上一级未通过时，下一级不应判定为通过。

## 4. 出口标准（建议）
- 日常合并最小口径：至少达到 L2。
- 提测口径：至少达到 L3。
- 里程碑/发布前口径：达到 L4。
